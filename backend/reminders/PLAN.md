# AWS event reminders

1. Keep the static Cloudflare website. Add an AWS HTTP API for checkbox-only email signup and unsubscribe, plus a read-only event catalog. Do not require an email confirmation click.
2. Deploy `roc-startup-week-api` and `roc-startup-week-reminder-sender`, a dedicated DynamoDB table, SES configuration set, SNS feedback topic, EventBridge rule, IAM roles, and CloudWatch logs/alarms in a `roc-startup-week-reminders` CloudFormation stack. Never change Locke/UVC identities or resources.
3. Generate the email event catalog from `collateral/data.mjs`. Use America/New_York, include additional days, and omit events without a known start time. Bundle the same catalog into Lambda and the website.
4. Require explicit checkbox consent. Homepage forms select all upcoming timed events; the detailed form supports individual selections. Activate immediately and record consent timestamp/version. Send a combined itinerary at 6 p.m. the previous evening for selected events, plus one 8 a.m. roundup of all that day's headliners to every opted-in subscriber. Never send separate emails per headliner. Skip send times that passed before signup. Retry only within one hour of the scheduled send time. Unsubscribe stops all notifications and public signup does not silently reactivate an unsubscribed address. Suppress permanent bounces and complaints through authenticated SNS invocation.
5. Run the sender every minute. Scan subscribers at this small event's scale, paginate, and conditionally claim delivery records to prevent concurrent sends. Retry failures. SES has no idempotency key: an ambiguous success followed by a process crash can cause a duplicate after lease expiry; exactly-once delivery is not promised.
6. Add a standalone reminder page and homepage link. Keep organizer registration separate. Deploy the AWS infrastructure, then smoke-test without contacting real attendees. Do not deploy the live website without explicit authorization.
7. Verify `remind.rocstartupweek.com` using DNS. Send as `Roc Startup Week <reminders@remind.rocstartupweek.com>`. Production sending stays disabled until the dedicated domain is verified. Preserve existing account-level SES settings.
8. Send one first-registration welcome email with the complete simple schedule and the website's latest PDF URL. Deduplicate by subscriber, retry at most three times within an hour, and enforce an atomic 1,000-send-attempt daily budget for the entire service. Use website detailed descriptions verbatim in reminder cards; keep the welcome schedule compact.

## Operations

Redeploy after schedule changes so both catalogs update. The worker derives due times from the current bundled catalog, so changes apply to unsent reminders without a database migration. Already-sent daily notification categories are not resent. Removing an event cancels its unsent reminders. Monitor Lambda errors and SES feedback; an EventBridge failed-invocation alarm covers scheduler failures. Subscriber records expire 90 days after the last event. API logs must never include bodies, email addresses, or tokens.
